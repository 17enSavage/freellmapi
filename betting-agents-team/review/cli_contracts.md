## (a) qualitative.json -> adjust
- model.py `adjust` (apply_adjustments) NEVER reads qualitative.json. It reads db table `adjustments`: `SELECT match_key, team, side, multiplier FROM adjustments WHERE run_id=? AND analyst='aggregated'`.
- Row schema: run_id, match_key, team (== model_output payload home/away CANONICAL name, exact match), side ('attack'|'defense'), multiplier, analyst='aggregated', reasoning, sources(JSON), flags(JSON), created_at NOT NULL; CHECK 0.80..1.30; UNIQUE(run_id,match_key,team,side,analyst).
- Loader: NONE in model.py, db.py, backtest.py, fetch_odds.py, report.py, smoke_test.py (no INSERT INTO adjustments anywhere; schema comment says sole writer = research-lead, no CLI). run_pipeline_*.py/validate.py not visible to me - caller should grep `INSERT.*adjustments`. report.py only reads qualitative.json for data_quality_flags. model.load_adjustments() is dead code.
- Needed loader mapping: for each payload[] item: teams from model_output (match_key -> home/away canonical); rows (home,attack),(home,defense),(away,attack),(away,defense) from payload[].home/away.{attack,defense}, reasoning, sources, flags; analyst='aggregated'. Re-run for same run_id leaves old rows unless deleted/replaced.

## (c) League spellings
- DB/canonical (db.py schema comment, backtest FDC_LEAGUES, fetch_odds SPORTS keys, CONTRACTS): EPL, La_liga, Bundesliga, Serie_A, Ligue_1, RFPL. All SQL equality = case-sensitive; no alias layer in these scripts.
- Divergent: fetch_odds docstring "La_Liga" (wrong); football-data codes E0/SP1/D1/I1/F1 only valid for fetch_fdc --divisions (smoke uses E0, seasons "2425"); fetch_understat uses same names (smoke: --leagues RFPL --seasons 2026). util.LEAGUES_UNDERSTAT not visible (used by model fit --all and backtest --all).
## (d) adjust math
- Yes: lam = lambda_home*kh_attack*ka_defense; mu = mu_away*ka_attack*kh_defense (each k clamped 0.80-1.25; lam,mu clamped 0.04-7.0); then score_matrix with params rho, blend with stored elo_probs by w_elo, recompute probs/fair/markets/top_scores/divergence; adjusted=True. defense>1 = team concedes more (raises opponent's lambda).
- Matches without rows: adjusted False, k_*=1.0, values untouched.
- 'skipped' status: irrelevant to adjust (never reads qualitative.json). With no rows it writes model_output_adjusted.json with adjustments_applied=0, status ok, exit 0. Missing model_output.json -> {"status":"failed"}, exit 1. Does not write adjusted rows into predictions table. Writes data/raw/{run}/model_output_adjusted.json (envelope + asof, upstream_artifact, adjustments_applied, matches, params_hashes, payload).
