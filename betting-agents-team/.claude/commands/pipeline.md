# Команда /pipeline

Аргументы: `$ARGUMENTS`

## Порядок действий

1. Делегировать агенту **`pipeline-orchestrator`** через Task, передав:
 - режим из `$ARGUMENTS` (по умолчанию `daily`)
 - текущую дату-время UTC как основу для `RUN_ID`
 - указание следовать `docs/ARCHITECTURE.md` (раздел «Полный конвейер одного дня»)

2. Ничего не делать самому. Не запускать этапы напрямую, не вызывать L1-агентов в обход оркестратора, не читать сырые данные.

## Разбор режимов

| Аргумент | Что делает оркестратор |
|---|---|
| `daily` | Полный конвейер: шаги 0–11 из его промта |
| `weekly` | `daily` + обязательный вызов `backtester` с недельным регрессионным контролем |
| `backtest --all --seasons Y` | Только `backtester`, без сбора данных и без ставок |
| `status` | Только чтение: `python3 pipeline/db.py status` и `python3 pipeline/value.py bank-status`, вывод таблицей. Агентов не вызывать |
| `validate --gate GATE_N` | Только `contract-validator` на указанном гейте (`GATE_1`…`GATE_4`, `GATE_5_BET_SLIP`) |

## Обязательная финальная проверка

После возврата оркестратора проверить наличие артефактов прогона:
```bash
ls -la data/raw/{RUN_ID}/ && tail -20 logs/audit.jsonl
```

Если хотя бы один ожидаемый артефакт отсутствует — сообщить человеку явно, какой именно этап не оставил результата. Не объявлять прогон успешным по ответу оркестратора, если файлов нет.

## Запрещено

- Запускать ставки или рекомендовать их от себя
- Менять содержимое `bet_slip.json`
- Перезапускать проваленный gate более одного раза
- При провале любого gate продолжать конвейер
